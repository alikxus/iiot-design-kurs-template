# Проєктування індустріальних інтернет речей

Навчальний курс для спеціальності **174 «Автоматизація, комп'ютерно-інтегровані технології та робототехніка»**, 3 курс.

Курс повністю **онлайн/інтерактивний**: фізичних стендів немає — замість них ви пишете **симулятор** насосного агрегату й будуєте навколо нього повний IIoT-конвеєр.

## Що ви збудуєте

```
[Симулятор насоса] → [Edge-шлюз] —MQTT→ [Брокер] → [Ingest → БД часових рядів]
                                              ├──→ [Рушій сповіщень → alerts]
                                              └──→ [Аналітика: аномалії, RUL]
```
З безпекою (автентифікація, ACL, підпис повідомлень) та розгортанням у Docker Compose.

## Старт
1. **Зробіть fork** цього шаблону у власний акаунт і клонуйте його.
2. Потрібно: Python 3.10+, Git, брокер MQTT (Mosquitto; для лаб. 7 — Docker).
3. Середовище:
   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```
4. Читайте лекцію тижня, потім методичку лабораторної в `labs/`.

## Як влаштовані лабораторні
- Ви **самі пишете код** у пакеті `iiot/` (готових заготовок немає — лише опис інтерфейсів у методичці).
- Кожна лабораторна має **автотести** в `tests/`. Запуск:
  ```bash
  python -m pytest tests/test_lab1_sim.py -v     # одна лабораторна
  python -m pytest -v                            # усе
  ```
- Тести — це мінімальні вимоги до інтерфейсу. Зелені тести ≠ повна оцінка: на **захисті** ви пояснюєте рішення й відповідаєте на питання.
- Інтеграційні тести лаб. 2 і 7 виконуються, якщо на `localhost:1883` працює брокер без автентифікації:
  ```
  # mosquitto.conf
  listener 1883
  allow_anonymous true
  ```
  `mosquitto -c mosquitto.conf`

## Структура репозиторію
```
lectures/     конспекти лекцій
labs/         методичні вказівки до лабораторних
tests/        автотести
iiot/         ВАШ код (наповнюється по ходу курсу)
deploy/       Docker-файли (лаб. 7)
docs/         ваша документація: ТЗ, архітектура, безпека, TCO
```

## Правила
- Робота індивідуальна; допускається обговорення ідей, але не копіювання коду.
- Паролі, ключі, `.env`, `passwd` — **ніколи** не комітяться.
- Захист кожної лабораторної — в реальному часі: коротка демонстрація + питання.
- Комітьте часто; повідомлення комітів — змістовні (`lab2: add offline buffer`).
