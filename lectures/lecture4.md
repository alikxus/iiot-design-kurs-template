# Лекція 4. Моніторинг, сповіщення та візуалізація

**Тиждень 4 · 2 академічні години · лабораторна: рушій сповіщень з гістерезисом і debounce**

## Мета
Навчитися проєктувати сповіщення так, щоб вони були корисними, а не шумними, та реалізувати конфігурований рушій правил.

## 1. Від даних до рішень
Дашборд відповідає на питання «що відбувається?», сповіщення — «що потребує дії **зараз**?». Погані сповіщення гірші за їх відсутність: оператори перестають на них реагувати (*alarm fatigue*).

Принципи (за ідеями ISA-18.2 / EEMUA 191):
- кожне сповіщення має **дію** — що робити оператору;
- кожне має **пріоритет** (info / warning / critical);
- кількість сповіщень — керована (орієнтир: хвилини між сповіщеннями, а не секунди);
- правила переглядаються за статистикою спрацювань.

## 2. Типи правил
| Тип | Приклад |
|---|---|
| Поріг | вібрація > 4,5 мм/с |
| Швидкість зміни | температура росте > 5 °C/хв |
| Відсутність даних (heartbeat) | немає телеметрії > 30 с |
| Складене | тиск низький **і** струм високий (ознака засмічення) |
| Аномалія | відхилення за z-оцінкою (лекція 5) |

## 3. Проблема «дрижання» (flapping)
Значення коливається біля порога → сповіщення то з'являється, то зникає. Два стандартні засоби:

**Debounce (антидребезг)** — підняти сповіщення лише після N поспіль вимірів вище порога (або після T секунд).

**Гістерезис** — знімати сповіщення, коли значення впало нижче `high − hysteresis`, а не нижче `high`.

Поріг 4,5; значення по черзі: `4.4, 4.6, 4.4, 4.6, 4.8, 4.9, 4.4, 4.2, 3.9`.

- **Без захисту**: raise на 2-му значенні, clear на 3-му, raise на 4-му, clear на 7-му — чотири переходи на дев'ять вимірів.
- **З debounce=3 та hysteresis=0.5**: raise лише на 6-му значенні (4.9 — третє поспіль вище порога); `4.4` і `4.2` ще не знімають сповіщення (вони не нижчі за 4.0); clear — на `3.9`. Усього два переходи.

## 4. Конфіг-орієнтований дизайн
Правила — це **дані**, а не код:

```python
from dataclasses import dataclass

@dataclass
class Rule:
    name: str
    metric: str
    high: float
    hysteresis: float = 0.0
    debounce: int = 3
    severity: str = "warning"

RULES = [
    Rule("high_vibration", "vibration_mm_s", high=4.5, hysteresis=0.5, severity="critical"),
    Rule("high_temperature", "temperature_c", high=80.0, hysteresis=3.0, debounce=5),
]
```

Рушій зберігає **стан для кожної пари (пристрій, правило)** і генерує події лише при **переходах** стану (`raised`, `cleared`), а не на кожен вимір.

```python
def process(msg):               # псевдокод
    for rule in rules:
        st = state[(msg.device_id, rule.name)]
        if not st.active:
            st.count = st.count + 1 if value > rule.high else 0
            if st.count >= rule.debounce:  raise_event()
        elif value < rule.high - rule.hysteresis:
            clear_event()
```

## 5. Доставка сповіщень
- **Окремий топік** `.../alerts` (події, а не потік) — на нього підписуються месенджери, SCADA, журнал.
- Подія містить: правило, пристрій, метрику, значення, час, серйозність, стан.
- Канали: дашборд, e-mail, Telegram/Slack-бот, SMS; для critical — ескалація, якщо немає підтвердження (acknowledge).
- Журнал подій зберігається для аудиту та аналізу спрацювань.

Приклад події:

```json
{"rule":"high_vibration","device_id":"pump-01","metric":"vibration_mm_s",
 "state":"raised","value":5.1,"ts":1760000123.4,"severity":"critical"}
```

## 6. Візуалізація
Інструмент: Grafana (дашборди над TimescaleDB/InfluxDB/Prometheus; для SQLite потрібен плагін). Що показувати:
- **Огляд**: статус кожного пристрою (online/offline з retained-топіка), число активних сповіщень.
- **Деталі**: тренди вібрації/температури зі смугами порогів, хвилинні min/avg/max.
- **Якість даних**: частота повідомлень, затримка, відсоток пропусків.

Практичні поради: одиниці на осях; кольори порогів ті ж, що й у правилах; не більше 6–8 панелей на екран; шкала часу за замовчуванням — остання година.

## 7. Тестування правил
Правило — це функція від послідовності значень. Тестуйте **послідовностями**: «5,5,1,5,5,1 → подій немає»; «5,5,5 → raised»; «5,5,5,4.2,3.9 → raised, cleared». Саме такі тести ви маєте в лабораторній.
