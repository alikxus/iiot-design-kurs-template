# Лекція 5. Цифровий двійник та предиктивне обслуговування

**Тиждень 5 · 2 академічні години · лабораторна: аномалії та оцінка залишкового ресурсу**

## Мета
Ознайомитися з рівнями цифрового двійника, стратегіями обслуговування та реалізувати прості, інтерпретовані методи виявлення аномалій та оцінки RUL.

## 1. Стратегії обслуговування
1. **Реактивне** — ремонт після поломки. Дешево, поки не стається аварія.
2. **Планово-попереджувальне** — за календарем/напрацюванням. Ремонтуємо те, що ще справне.
3. **За станом** (condition-based) — за вимірами (вібрація, температура).
4. **Предиктивне** — прогнозуємо, **коли** параметр досягне межі, і ремонтуємо у зручне вікно.

## 2. Цифровий двійник: три рівні
- **Цифрова модель** — опис без зв'язку з реальним об'єктом (креслення, симуляція).
- **Цифрова тінь** — дані з об'єкта надходять у модель (односторонній зв'язок). *Наш симулятор + конвеєр — це тінь.*
- **Цифровий двійник** — двосторонній зв'язок: модель впливає на реальний об'єкт (уставки, рекомендації).

Практичний патерн «device shadow»: для кожного пристрою зберігаємо `reported` (що пристрій повідомив) і `desired` (що хочемо) та розбіжність між ними.

## 3. Вібрація як індикатор стану
Інтегральна швидкість вібрації (мм/с RMS) — класичний показник стану підшипників і дисбалансу. Стандарт ISO 10816-3 (замінений ISO 20816-3) визначає зони стану: A — новий, B — допустимо тривало, C — обмежено, D — небезпечно. Для машин групи 2 (15–300 кВт) на жорсткому фундаменті межі зон приблизно: 1,4 / 2,8 / 4,5 мм/с (перевіряйте за актуальним стандартом для свого обладнання). Звідси наш поріг 4,5 мм/с для critical.

Типовий сценарій деградації (крива P–F): тривалий період «норми» → поява перших ознак (P) → прискорене зростання → функціональна відмова (F). Інтервал P–F — вікно для планування ремонту.

## 4. Виявлення аномалій простими методами

### 4.1 Експоненційне згладжування (EWMA)
Прибирає шум, залишаючи тренд: `s_t = α·x_t + (1−α)·s_{t−1}`; малий α — сильніше згладжування.

```python
def ewma(values, alpha=0.3):
    out, s = [], None
    for v in values:
        s = v if s is None else alpha * v + (1 - alpha) * s
        out.append(s)
    return out
```

### 4.2 Ковзна z-оцінка
Порівнюємо нове значення з середнім і стандартним відхиленням **попереднього вікна**:

`z = (x − mean) / std`; аномалія, якщо `|z| > поріг` (типово 3–4).

```python
from collections import deque
import math

class RollingZ:
    def __init__(self, window=30, min_samples=10):
        self.buf, self.min_samples = deque(maxlen=window), min_samples
    def update(self, x):
        z = None
        if len(self.buf) >= self.min_samples:
            mean = sum(self.buf) / len(self.buf)
            std = math.sqrt(sum((v - mean) ** 2 for v in self.buf) / len(self.buf))
            z = (x - mean) / max(std, 1e-6)
        self.buf.append(x)       # додаємо ПІСЛЯ обчислення
        return z
```

Важливі нюанси: «розігрів» (до накопичення вікна повертаємо `None`); нове значення не входить у власне вікно; повільний дрейф z-оцінка **не** ловить — тому поруч потрібен трендовий метод.

## 5. Оцінка залишкового ресурсу (RUL)
Лінійна регресія методом найменших квадратів: `v ≈ a·t + b`, де
`a = Σ(t−t̄)(v−v̄) / Σ(t−t̄)²`, `b = v̄ − a·t̄`.

Час перетину межі `L`: `t* = (L − b)/a`; RUL = `t* − t_now`.

```python
def linear_trend(ts, values):
    n = len(ts); mt, mv = sum(ts)/n, sum(values)/n
    sxx = sum((t - mt) ** 2 for t in ts)
    slope = sum((t - mt) * (v - mv) for t, v in zip(ts, values)) / sxx if sxx else 0.0
    return slope, mv - slope * mt

def estimate_rul(ts, values, limit):
    if values[-1] >= limit: return 0.0           # межу вже перевищено
    slope, icpt = linear_trend(ts, values)
    if slope <= 1e-12: return None               # тренду до межі немає
    return max((limit - icpt) / slope - ts[-1], 0.0)
```

**Обмеження**: деградація зазвичай нелінійна (прискорюється) → лінійна оцінка **оптимістична**; використовуйте короткі вікна (останні години), показуйте користувачу **невизначеність** (діапазон, а не одне число), а в критичних випадках — експоненційні/фізичні моделі чи ML.

## 6. Місце ML
Прості методи — інтерпретовані й не потребують розмічених даних. Далі за потреби: Isolation Forest / автоенкодер (аномалії без розмітки), градієнтний бустинг/LSTM (RUL при наявності історії відмов). Правило: **спочатку базова лінія** (поріг + тренд), потім ML — і лише якщо він її перевершує на історичних даних.
