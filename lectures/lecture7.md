## Мета
Навчитися пакувати IIoT-рішення в контейнери, конфігурувати його через середовище, документувати та оцінювати вартість володіння.

## 1. Життєвий цикл IIoT-проєкту
1. Обстеження й вимоги → 2. Архітектура → 3. Прототип на симуляторі → 4. Пілот на одному агрегаті → 5. Масштабування → 6. Експлуатація та супровід.

Принцип: **маленький наскрізний зріз працює раніше, ніж «ідеальна» архітектура**. У курсі кожна лабораторна додає ланку до єдиного конвеєра.

## 2. Конфігурація (12-factor)
- Конфіг — у **змінних середовища**, не в коді.
- Один і той самий образ — для всіх середовищ.
- Секрети — окремо від конфігів; обов'язкові змінні перевіряються при старті.

```python
import os

class Config:
    def __init__(self, env=None):
        e = os.environ if env is None else env
        self.mqtt_host = e.get("MQTT_HOST", "localhost")
        self.mqtt_port = int(e.get("MQTT_PORT", "1883"))
        self.device_id = e.get("DEVICE_ID", "pump-01")
        self.signing_key = e["SIGNING_KEY"].encode() if e.get("SIGNING_KEY") else None
```

## 3. Контейнеризація

**Dockerfile** (мінімальний):

```dockerfile
FROM python:3.12-slim
WORKDIR /app
RUN pip install --no-cache-dir "paho-mqtt>=2.0"
COPY iiot ./iiot
ENV PYTHONUNBUFFERED=1
```

**Docker Compose** описує весь стек декларативно: сервіси, мережу, томи, залежності, health-check.

```yaml
services:
  mosquitto:
    image: eclipse-mosquitto:2
    ports: ["1883:1883"]
    volumes: ["./mosquitto.conf:/mosquitto/config/mosquitto.conf:ro"]
  gateway-pump01:
    build: {context: ., dockerfile: deploy/Dockerfile}
    command: python -m iiot.services.gateway_service
    environment: {MQTT_HOST: mosquitto, DEVICE_ID: pump-01}
    depends_on: [mosquitto]
    restart: unless-stopped
```

Корисні команди: `docker compose up --build -d`, `docker compose ps`, `docker compose logs -f ingest`, `docker compose down`.

**Health-check**: сервіс періодично «торкається» файла; перевірка — свіжість `mtime`. Для HTTP-сервісів — окремий `/health`.

**Томи**: стан (БД, дані брокера) — у іменованих томах; контейнер можна перестворити без втрати даних.

## 4. Спостережуваність
- **Логи** — у stdout, структуровані, з рівнями.
- **Метрики** — лічильники (отримано/відкинуто/записано), довжина буфера, затримка.
- **Трейси** — наскрізний `ts` в повідомленні дозволяє міряти затримку «вимір → сповіщення».

## 5. Документація проєкту
Мінімальний пакет:
1. **ТЗ** (лекція 1) — з критеріями приймання.
2. **Архітектурний опис**: схема компонентів, потоки даних, простір топіків, контракт повідомлення.
3. **Інструкція розгортання** (`README`): передумови, команди, перевірка.
4. **Модель загроз і налаштування безпеки** (лекція 6).
5. **План тестування** і результати (`pytest`).
6. **Експлуатація**: що робити при відмові, резервне копіювання, ротація секретів.

Критерій якості: інша людина розгортає систему за вашим README **без питань до вас**.

## 6. Економіка: TCO
**Total Cost of Ownership** = CAPEX (обладнання, ліцензії, розробка) + OPEX (зв'язок, хмара/сервери, супровід, навчання) за строк життя.

Приклад структури оцінки для пілоту на 20 агрегатів:
- Датчики та шлюзи: кількість × ціна.
- Монтаж і інтеграція: людино-години × ставка.
- Інфраструктура: сервер/хмара (обсяг даних із лекції 3 × тариф).
- Супровід: частка ставки інженера на рік.
- Ліцензії: Grafana/Influx/Timescale — відкриті версії безкоштовні, enterprise — платні.

**Ефект**: уникнені простої × вартість години простою; зменшення аварійних ремонтів; оптимізація запчастин. Простий показник — **термін окупності** = витрати / річний ефект.

Приклад (умовні числа): витрати 600 тис. грн; уникнений простій 3 год/рік × 150 тис. грн/год = 450 тис. + заощадження на аварійних ремонтах 150 тис. = 600 тис./рік → окупність ≈ 1 рік. Завжди показуйте **припущення** окремо від результату.

## 7. Підсумковий проєкт і захист
Студент демонструє:
1. Запуск стека однією командою.
2. Потік даних від симулятора до БД; статус пристрою.
3. Спрацювання сповіщення при ін'єкції несправності.
4. Роботу захисту (відхилення підробленого/повторного повідомлення, заборона чужого топіка).
5. Відповіді на питання за архітектурою та ТЗ.
